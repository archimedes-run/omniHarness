# The app kit's shim and client

Spec 011 FR-018, FR-023, FR-025. The coding job's app mode copies these files into
every app project:

| File           | What it is                                                                                                                                                                                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `omni-shim.js` | The platform shim. Inlined as the FIRST script of the app's HTML. Generated by `node scripts/build-app-shim.mjs` from `omni-shim.src.js`, `../protocol.schema.json` and `../validate.js`, so the shim checks messages with the same schema and the same function as the host page. Do not edit it by hand. |
| `omni.d.ts`    | Types for `window.omni`. The kit generates `OmniSources` from the app's `omni-app.json` so that `omni.data("calendar")` is typed.                                                                                                                                                                          |

**The gateway carries its own copy.** Registration injects the shim from
`backend/app/gateway/apps/kit/omni-shim.js`, which must stay byte-identical to
`omni-shim.js` here. After regenerating the shim, copy it there in the same
change (compare `shasum -a 256` of the two).

## What an app can do

An app has no network: `fetch`, XHR, WebSocket, EventSource, beacons, remote
images, CSS `url()` to anywhere, forms, popups, top navigation, nested frames and
workers are all blocked, and it may only be shown inside OmniHarness's own app
page (the shim's first act is to say hello to that page; an app document that
reloads or replaces itself is closed). Images and fonts must be `data:` URLs; charts are inline
SVG. It talks to the host page only through `omni`:

```js
const r = await omni.data("calendar");  // one source, by its manifest name
omni.refresh("calendar");                // ask for a refetch
omni.open(link);                         // https on a declared host, or /workspace/...
omni.connect("calendar");                // the host shows its own Connect sheet
omni.onTheme((t) => ...);                // "light" | "dark"; <html> gets .dark
omni.onUpdate((name, result) => ...);    // the host refreshed a source
```

Plain `<a href>` clicks are routed through `omni.open` for you. Links the host does
not allow are refused with an error (`omni.onError`).

## Tile states (every tile handles all four)

Use these words, so every app reads the same. `omni.describe(result)` returns them.

| `state`         | The tile shows                                                                               | Notes                                                   |
| --------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `fresh`         | The data, and **"updated 4 min ago"** from `fetched_at` (`omni.ago`).                        | If `stale` is true, add "May be out of date".           |
| `not_connected` | **"Not connected"** and a **Connect** button calling `omni.connect(name)`.                   | Never start sign-in yourself; the host's sheet does it. |
| `failed`        | **"Can't tell"** and the `reason`. If `data` is not null, show it marked stale.              | Never "Nothing today": a failure is not an empty day.   |
| `empty`         | **"Nothing today"** (or the tile's own wording of nothing, such as "No PRs waiting on you"). | Only for `empty`, never for `failed`.                   |

While the first answer is on its way, show a quiet placeholder of the tile's size,
not a spinner over the whole page.

## No HTML from strings, no frames

The app document's CSP carries Trusted Types with no policy allowed:

```
require-trusted-types-for 'script'; trusted-types 'none'
```

So every API that turns a string into HTML or script throws: `innerHTML`,
`outerHTML`, `insertAdjacentHTML`, `document.write`, `DOMParser`,
`createContextualFragment`, `setHTMLUnsafe`, `iframe.srcdoc`, `script.text`,
`javascript:` URLs. The shim also refuses every frame element (`iframe`, `frame`,
`object`, `embed`...) however it is made, and removes XSLT.

What still works, and is all an app needs: `document.createElement`,
`textContent`, `setAttribute` (except `srcdoc` and event handlers),
`appendChild`/`append`/`replaceChildren`, `classList`, `style`, SVG through
`createElementNS`, and `<style>` text.

- **React** renders through these DOM calls and works. Never use
  `dangerouslySetInnerHTML`.
- **Plain DOM code** works. Never assign HTML strings; build nodes.
- Frameworks that stamp templates with `innerHTML` (Svelte 5, Lit, Vue's
  stringified static content) do not work under this policy. Do not use them.

## Rules

- Single self-contained file: no dynamic imports, no remote URLs, no `eval`, no
  `new Function`, no `WebSocket`, no `RTCPeerConnection` (registration refuses them).
- No `innerHTML` or any other HTML-from-string API, and no frame elements (above).
- Responsive from 360 px; touch targets at least 24 px; no text under 12 px.
- Use the Graphite tokens (`graphite.css`) in both themes.
